# Unify P3 — Chrome extensions

Built 2026-10-13/14 on the `unify` branch (`330033de`, `60331561`, `5baf2f78`
and the commit that adds this file). Electron 41.2.1 (Chromium 146).

## What you get

- **Install from the Chrome Web Store.** Open the store in a task's tab and
  click **Add to DEX** (the store's "Add to Chrome", relabelled), or paste a
  store link or an id in **Settings › Extensions**. DEX shows Chrome's
  permission wording first ("Read and change all your data on all websites").
- **Use them like in Chrome.** Content scripts run on the pages in your
  tasks. Pinned extensions sit in the browser toolbar with their badges;
  the puzzle piece lists all of them. A click opens the extension's popup
  under its button; right-click gives its menu (Options, Pin, Remove).
  Their right-click items appear in the page's own menu.
- **Manage them.** Settings › Extensions: on/off, pin, Options, Remove, "What
  it can do", file-URL access, Load unpacked and Check for updates for
  developers. Store installs update themselves every five hours.
- **Only in DEX's browser.** Extensions load into the web profile
  (`persist:dex-web`), never into DEX's own windows (hub, Logs, pill).

## How it's built

```
Chrome Web Store page ──(preload/storeBridge.ts: chrome.webstorePrivate)──► main/extensions/webStore.ts
                                                                              │
Settings › Extensions, toolbar ──(electronAPI.extensions)──────────────────► │
                                                                              ▼
                                    ExtensionManager (install, verify, update, state.json)
                                                                              │ loadExtension
extension service worker ─┐                                                   ▼
extension page (popup) ───┴─ preload/extensionShim.ts ── IPC ──► ExtensionHost (calls, events, popups)
                                                                   ├─ tabsApi      (each task = a window; tab id = webContents id)
                                                                   ├─ actionApi    (button state per tab)
                                                                   ├─ menusApi     (+ workspace/pageContextMenu.ts)
                                                                   ├─ dnr/         (declarativeNetRequest engine)
                                                                   ├─ webRequestHub (the web profile's only request hooks)
                                                                   ├─ proxyApi, cookiesApi, webNavigationApi, permissionsApi,
                                                                   │  platformApi (notifications, idle, offscreen, identity…),
                                                                   └─ syncStorage  (storage.sync)
```

- **Verified installs** (`crx.ts`): every signature in the CRX3 checks out,
  one key hashes to the id we asked for, and the Chrome Web Store's own
  publisher key signed it (the check `electron-chrome-web-store` skips).
  Checked against real store packages; one flipped byte is refused.
- **The shim** runs in each extension's own world before its code
  (`registerPreloadScript` for service workers and frames +
  `contextBridge.executeInMainWorld`). It's serialized into that world, so it
  is self-contained; a test runs it from its source text in an empty `vm`
  context to keep it that way.
- **Who is calling** is never taken from the call: a worker's extension
  comes from its scope, a page's from its frame's own address; anything
  outside the web profile is refused. Every API checks the caller's
  permissions (tabs' URLs only with `tabs`/host access/activeTab, cookies
  per host, and so on).
- **Events** wake a sleeping worker that listened before, as Chrome does,
  and arrive once its listeners are back (`__ready`).
- **declarativeNetRequest** (`dnr/`): rules indexed by their rarest
  5-character literal or by domain; Chrome's priorities and tie order
  (allow > allowAllRequests > block > upgradeScheme > redirect), block from
  any extension wins, the newest extension's redirect otherwise;
  allowAllRequests per frame; redirects (url, extensionPath, regex
  substitution, transform); header changes. **Load 270 ms for uBO Lite's
  18,755 rules; ~28 µs per request.**

## Security review

- Extensions run with your logged-in web profile, as in Chrome. They are
  never loaded in DEX's own windows (the hub uses the default session).
- `file://` only when you tick "Allow access to files" for that extension.
- **The agent and extensions** (`cdpBroker.ts` hooks):
  - a tab showing a **password manager's** own page (Bitwarden, 1Password,
    LastPass, Dashlane, Keeper, NordPass, RoboForm, Proton Pass, Enpass,
    KeePass, Zoho Vault, Norton) is left out of the agent's targets, and
    commands stop if a tab it holds goes there;
  - **extensions' frames inside a page** (an inline password menu, a
    writing assistant's panel) are detached as soon as auto-attach reaches
    them, including a page frame that navigates into one;
  - other extensions' own pages can be opened as a tab and driven, as the
    plan wanted; `tabs.md` tells the agent to ask first.
- Extension code is untrusted: every API checks its arguments and the
  caller's permissions in main; URLs an extension opens are limited to
  http(s), about:blank and extension pages.
- The Web Store bridge answers only the store's own origin in the web
  profile. Removing an extension from the store page asks you first.
- Site permissions (camera, location…) for pages are DEX's own prompts
  (`workspace/sitePermissions.ts`): asked only when you were using the tab,
  never granted to a page nobody is looking at.

## Known gaps

- **Blocking webRequest** (MV2, or MV3 policy installs) isn't offered;
  extensions observe. declarativeNetRequest covers blocking.
- DNR rules with **response-header conditions** never match; "first party"
  uses a short list of multi-label suffixes, not the full Public Suffix List.
- **Keyboard shortcuts** from `commands` aren't dispatched yet.
- **Per-site access** ("on click" / "on specific sites") isn't offered;
  host permissions are granted as the manifest asks.
- A site's own **basic-auth / proxy sign-in prompt** isn't drawn by DEX;
  only extensions can answer `onAuthRequired` today.
- `chrome.downloads` isn't implemented.
- Chromium shares page zoom between tabs of one site, so two tabs of a site
  share the "fit to pane" zoom (the tab in front gets its own back).
